One-shot channels: a single value handed from one task to another.

§Blocking

Receiver::recv parks the calling thread, which on wasm is the browser’s only thread: it hangs the event loop with no diagnostic, unlike block_on and read_sync, which handle that target explicitly. Await the receiver instead — that works everywhere. The blocking receive is only used from multi_threading code paths.

Absent on a target whose atomics carry no compare-and-swap (thumbv6m): oneshot needs it and has no fallback. Every consumer needs std or the browser, so nothing that could run there loses anything.
