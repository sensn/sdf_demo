Module attribute

Attributes are non-SSA data stored in Operations.

See MLIR Attributes. Unlike in MLIR, we do not unique attributes, and hence they are mutable. These are similar in concept to Properties. Attribute objects are boxed and not wrapped with Ptr. They are heavy (i.e., not just a pointer, handle or reference), making clones potentially expensive.

The pliron_attr proc macro from the pliron-derive create can be used to implement Attribute for a rust type.

Common semantics, API and behaviour of Attributes are abstracted into interfaces. Interfaces in pliron capture MLIR functionality of both Traits and Interfaces. Interfaces must all implement an associated function named verify with the type AttrInterfaceVerifier.

Interfaces are rust Trait definitions annotated with the attribute macro attr_interface. The attribute ensures that any verifiers of super-interfaces are run prior to the verifier of this interface. Note: Super-interface verifiers may run multiple times for the same attribute.

Attributes that implement an interface must annotate the implementation with attr_interface_impl macro to ensure that the interface verifier is automatically called during verification and that a &dyn Attribute object can be cast into an interface object, (or that it can be checked if the interface is implemented) with ease.

Use verify_attr to verify an Attribute object. This function verifies all interfaces implemented by the attribute, and then the attribute itself. The attribute’s verifier must explicitly invoke verifiers on any sub-objects it contains.

AttrObjs can be downcasted to their concrete types using downcast_rs.
