Module op 

Source
Expand description

An Op is a thin wrapper arround an Operation, providing API specific to the OpId of that Operation.

See MLIR’s Op.

New Ops can be easily declared using the pliron_op proc macro from the pliron-derive crate.

Common semantics, API and behaviour of Ops are abstracted into Op interfaces. Interfaces in pliron capture MLIR functionality of both Traits and Interfaces. Interfaces must all implement an associated function named verify with the type OpInterfaceVerifier.

Interfaces are rust Trait definitions annotated with the attribute macro op_interface. The attribute ensures that any verifiers of super-interfaces are run prior to the verifier of this interface. Note: Super-interface verifiers may run multiple times for the same op.

Ops that implement an interface must annotate the implementation with op_interface_impl macro to ensure that the interface verifier is automatically called during verification and that a &dyn Op object can be cast into an interface object, (or that it can be checked if the interface is implemented) with ease.

Use verify_op or verify_operation to verify an Op object or Operation. The verifier methods of Op or Operation may not, by themselves do a complete verification.

OpObjs can be downcasted to their concrete types using downcast_rs.
