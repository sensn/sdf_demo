Every SSA value, such as operation results or block arguments has a type defined by the type system.

The type system is open, with no fixed list of types, and there are no restrictions on the abstractions they represent.

See MLIR Types

The pliron_type proc macro from [pliron-derive] can be used to implement Type for a rust type.

Common semantics, API and behaviour of Types are abstracted into interfaces. Interfaces in pliron capture MLIR functionality of both Traits and Interfaces. Interfaces must all implement an associated function named verify with the type TypeInterfaceVerifier.

Interfaces are rust Trait definitions annotated with the attribute macro type_interface. The attribute ensures that any verifiers of super-interfaces are run prior to the verifier of this interface. Note: Super-interface verifiers may run multiple times for the same type.

Types that implement an interface must annotate the implementation with type_interface_impl macro to ensure that the interface verifier is automatically called during verification and that a &dyn Type object can be cast into an interface object, (or that it can be checked if the interface is implemented) with ease.

Use verify_type to verify a Type object. This function verifies all interfaces implemented by the type, and then the type itself. The type’s verifier must explicitly invoke verifiers on any sub-objects it contains.

TypeHandles can be TypeHandle::deref’d and downcasted to their concrete types using downcast_rs.
