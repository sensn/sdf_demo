Um den L1/L2-Cache der GPU-Kerne bei der Abfrage prozeduraler 3D-SDF-Räume optimal auszulasten, nutzen wir die räumliche Kohärenz (Spatial Coherence).
Wenn benachbarte Threads im selben Warp auf nahegelegene Speicher- oder Geometriebereiche zugreifen, führt dies zu einer perfekten Cache-Hit-Rate in den Execution Units der GPU. Durch die Dynamik unseres vorherigen Stream-Compaction-Schrittes (copy_where) fliegen jedoch kontinuierlich Strahlen aus dem flachen Vektor. Das führt dazu, dass nach einigen Schritten die verbleibenden Strahlen im DeviceVec kreuz und quer über den Bildschirm verteilt sind. Threads innerhalb desselben Hardware-Warps berechnen plötzlich völlig unterschiedliche Raumbereiche – der Cache wird "vergiftet" (Cache Thrashing).
Mit massively::vector::sort_by_key sortieren wir die aktiven Strahlen nach einer räumlichen Kennzahl (einem räumlichen Hash oder der Pixel-ID). Dadurch werden Strahlen, die geometrisch nah beieinander liegen, wieder in benachbarten GPU-Threads gebündelt (Warp-Kohärenz).

Schritt 1: Generierung des Sortierschlüssels (UnaryOp)

Wir weisen jedem Strahl einen eindeutigen Sortierschlüssel zu. Da wir die Strahlen anhand ihrer initialen Pixel-Positionen oder ihres aktuellen Raumbereichs gruppieren wollen, extrahieren wir einen 32-Bit-Index. In diesem Fall nutzen wir einen schnellen Raum-Mörtel- oder Gitter-Hash ihrer aktuellen Position origin.
rust
use cubecl::prelude::*;
use massively::op::UnaryOp;

pub struct SpatialKeyGenerator {
    pub grid_scale: f32,
}

#[cubecl::cube]
impl UnaryOp<RayState> for SpatialKeyGenerator {
    // Der Sortierschlüssel ist ein u32-Index des Raumbereichs (MIndex)
    type Output = u32;

    fn apply(ray: RayState) -> u32 {
        // Diskretisiere die 3D-Position in ein grobes räumliches Gitter
        let ix = u32::cast(f32::floor(ray.origin.x * self.grid_scale));
        let iy = u32::cast(f32::floor(ray.origin.y * self.grid_scale));
        let iz = u32::cast(f32::floor(ray.origin.z * self.grid_scale));

        // Erzeuge einen einfachen, schnellen Linearschlüssel für das Sortieren
        // (Räumliches Clustern / Morton-artig vereinfacht)
        (ix & 0x3FF) | ((iy & 0x3FF) << 10) | ((iz & 0x3FF) << 20)
    }
}

Schritt 2: Die optimierte Hauptschleife mit periodischer Sortierung

Das Sortieren auf der GPU ist dank massively extrem schnell (Thrust-Style Radix Sort), sollte aber dennoch nicht in jedem einzelnen Schritt ausgeführt werden, um den Overhead gering zu halten. Ein Intervall von alle 4 bis 8 Schritten ist der Sweetspot, um die Kohärenz intakt zu halten.
rust
use massively::{Executor, vector::{map, copy_where, sort_by_key}};
use cubecl::wgpu::WgpuRuntime;

fn run_coherent_massively_raymarcher(
    exec: &Executor<WgpuRuntime>,
    init_rays: Vec<RayState>,
    max_steps: u32,
    step_size: f32,
    time: f32,
    fog_density: f32,
) -> Result<Vec<RayState>, massively::Error> {
    
    let mut active_rays = exec.to_device(&init_rays);
    let step_op = SingleVolumeStep { step_size, time, fog_density };
    let key_op = SpatialKeyGenerator { grid_scale: 2.0 }; // Rastergröße für Cache-Bündelung

    for step in 0..max_steps {
        if active_rays.len() == 0 {
            break;
        }

        // 1. Homogener Volumenschritt für alle verbleibenden Strahlen
        let stepped_rays = map(exec, active_rays.slice(..), step_op)?;

        // 2. Stream Compaction: Tote Strahlen eliminieren
        let compact_rays = copy_where(exec, stepped_rays.slice(..), ActiveRayFilter)?;

        // 3. 🟢 CACHE-OPTIMIERUNG: Periodisches Resortieren zur Warp-Bündelung
        // Alle 8 Schritte sortieren wir die verbleibenden Daten im VRAM neu.
        if step % 8 == 0 && compact_rays.len() > 64 {
            // Generiere die Sortierschlüssel basierend auf der aktuellen Position (Lazy/Register-bound)
            let keys = map(exec, compact_rays.slice(..), key_op)?;

            // Sortiere die Strahlen direkt im Speicher nach dem räumlichen Schlüssel
            // sort_by_key gibt einen neu sortierten, dichten MVec zurück
            active_rays = sort_by_key(exec, compact_rays.slice(..), keys.slice(..))?;
        } else {
            active_rays = compact_rays;
        }
    }

    // Zurückholen der fertig berechneten, akkumulierten Pixeldaten
    exec.to_host(&active_rays)
}

Der architektonische FPS-Effekt im Detail:

• Maximale Cache-Hit-Rate: Wenn der SingleVolumeStep-Kernel im darauffolgenden Schritt z.B. das prozedurale 3D-Rauschen noise_3d berechnet, greifen alle 32 Threads innerhalb eines Warps auf exakt dieselben mathematischen Intervalle und dieselben Cache-Lines im L1/L2-Speicher der GPU zu.
• Keine ungenutzten Execution Units: Indem wir die verbleibenden Fragmente physisch im Speicher zusammenschieben und sortieren, minimieren wir die Speicherlatenz auf ein theoretisches Minimum.
Durch die Kombination aus Stream Compaction (Lastenreduzierung) und Spatial Sorting (Cache-Bündelung) kitzelt diese massively-Pipeline die maximale theoretische Rechenleistung aus deiner Vulkan/WGPU-Hardware heraus.
